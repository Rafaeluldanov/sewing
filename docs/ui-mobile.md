# UI: mobile clean redesign (Шаг 13)

> Чисто фронтовый редизайн поверх MVP 1.1. Бэкенд, API, auth-flow и
> бизнес-потоки не меняются — только верстка, токены и UX.

Цель — сделать веб-интерфейс системы понятным и приятным с телефона
для трёх ролей цеха:

- **швея** (`SEAMSTRESS`)
- **ВТО** (`IRONING`)
- **помощник закройщика** (`CUTTER_ASSISTANT`)

---

## 1. Принципы

- **Mobile-first.** Все рабочие экраны проектируются для вертикального
  телефона; десктоп получает увеличенные отступы и табличные
  представления (заказы / админка / `/shopfloor`).
- **Чисто и светло.** Белый фон, светло-серые карточки (`#f1f4f9`),
  тёмно-синий текст, мягкие синие акценты (`#2563eb`).
- **Минимум визуального шума.** Поля без лишних рамок, заголовки
  крупнее, вторичный текст приглушён (`--color-fg-muted`).
- **Крупные тач-цели.** Кнопки `min-height: 44 px`, primary-кнопки на
  `/work` — `56 px` (`.btn-lg`). Чекбоксы/чипсы — `48 px`.
- **Действие важнее статуса.** Сначала кнопка, потом результат, потом
  детали. Status-badge всегда вторичный.
- **Никакой агрессии в ошибках.** Светло-красная карточка,
  `requestId` мелким шрифтом — оператор знает, что назвать поддержке.
- **Фирменный тёмно-синий хедер** оставлен — это маркер бренда.
  Дальше интерфейс становится белым.

## 2. Дизайн-токены

Все токены задаются переменными в `apps/web/app/globals.css`
(`:root { … }`). Используйте только их — не подставляйте hex-цвета
напрямую в компоненты.

| Группа     | Токен                                          | Применение                       |
| ---------- | ---------------------------------------------- | -------------------------------- |
| Фон        | `--color-bg`, `--color-bg-soft`, `--color-bg-muted`, `--color-bg-tint` | страница / soft фоны / карточки / акцент-фон |
| Текст      | `--color-fg`, `--color-fg-muted`, `--color-fg-subtle` | основной / вторичный / совсем тонкий |
| Акценты    | `--color-accent`, `--color-accent-soft`, `--color-accent-fg` | primary-кнопки, ссылки, синие чипсы |
| OK         | `--color-ok`, `--color-ok-soft`, `--color-ok-fg` | success-карточки, годных |
| Warn       | `--color-warn`, `--color-warn-soft`, `--color-warn-fg` | предупреждения |
| Danger     | `--color-danger`, `--color-danger-soft`, `--color-danger-fg` | ошибки, брак |
| Граница    | `--color-border`, `--color-border-strong` | карточки / inputs |
| Радиусы    | `--radius-sm | -md | -lg | -xl | -pill` (8 / 12 / 16 / 22 px / 999) | соответственно |
| Тени       | `--shadow-xs | -sm | -md | -lg` | по убыванию интенсивности |
| Тач-цель   | `--tap-min` (48 px) | минимальная высота интерактивного элемента |

Старые алиасы (`--fg`, `--bg`, `--accent`, `--border`, `--ok` …)
сохранены, чтобы не ломать legacy-CSS из `/shopfloor`, `/admin` и
`/orders`.

## 3. Reusable-компоненты

Все живут в `apps/web/components/`:

- **`<RoleHeaderCard>`** — фирменная синяя «шапка-профиль» поверх
  `/work`: имя, роль, поля смены (операция, оборудование), индикатор
  статуса. Используется и при активной, и при неактивной смене (без
  полей).
- **`<MobileActionCard>`** — крупная action-карточка (иконка / заголовок
  / подсказка). Поддерживает варианты `default`, `primary`, `danger`.
  Может быть `<Link>` или `<button>`.
- **`<AppSectionCard>`** — мягкая серая секция с заголовком и
  подсказкой. Используется на детальной странице паспорта (Качество,
  Упаковка, Начисления, Размещение).
- **`<StatusPill>`** — компактный pill для произвольных подписей
  (`default | accent | ok | warn | danger | ghost`). Не вытесняет
  `<StatusBadge>` — тот всё ещё держит цвета статусов заказа.
- **`<MobileNav>`** — фиксированная нижняя навигация для ≤ 900 px.
  Видна только авторизованным пользователям, скрыта на десктопе.
- **`<LogoutButton>`, `<StatusBadge>`** — без визуальных изменений в
  поведении, только новые цвета через токены.

Не плодите новые компоненты ради новых компонентов: для одноразовых
секций достаточно `<AppSectionCard>` или `.card`.

### 3.1. Unified shopfloor namespace

`apps/web/components/shopfloor/index.ts` — единая точка входа для
рабочих мест сотрудников. Это **не новая дизайн-система**: namespace
ре-экспортит существующие канонические компоненты под единым префиксом
`@/components/shopfloor` и добавляет несколько тонких функциональных
обёрток над уже существующими CSS-классами `globals.css`.

| Имя из namespace | Что это | Под капотом |
|------------------|---------|-------------|
| `ShopfloorShell` | Контейнер рабочего места | `<div className="seamstress-work">` (без новых стилей) |
| `ScanPanel` | Скан-блок с заголовком и хинтом | `.scan-card.scan-card--simple` |
| `ProductionEmptyState` | Пустое состояние | `.card.empty` |
| `ProductionErrorState` | Ошибка с requestId/hint | `.error-box` |
| `ProductionLoadingState` | Inline-loader | `<p>Загрузка…</p>` |
| `RoleHeaderCard` / `WorkerStatusCard` / `ShopfloorPageTitle` | Шапка-профиль | алиасы того же `RoleHeaderCard` |
| `StatusBadge` / `ProductionStatusBadge` | Pill-бейдж | алиасы `StatusBadge` |
| `MobileActionCard`, `AppSectionCard`, `Icon`, `EmployeeQrButton` | Канонические компоненты | re-export из `apps/web/components/*` |

Подробности и решение «не плодить дубли»  — см.
[`docs/design-cleanup-recon.md`](./design-cleanup-recon.md).

## 4. Главные экраны

### 4.1. `/login`

- Полностраничный светлый фон, центрированная карточка `.auth-card`
  (max 420 px).
- Brand-mark (квадратик с буквой S), компактный заголовок,
  короткая подсказка, два input'а, primary-кнопка во всю ширину.
- Ошибка — мягкая красная плашка прямо под полями.

### 4.2. `/work` — главный мобильный кабинет

Поток для **швеи / ВТО / помощника закройщика**:

1. Сверху всегда — `<RoleHeaderCard>`. При активной смене показывает
   операцию и оборудование, индикатор «Смена с HH:MM»; при
   неактивной — «Смена не начата».
2. Если смены нет → **`ShiftStartForm`**: мягкая `.scan-card` с
   двумя селектами (оборудование, операция) и крупной кнопкой
   «Начать смену».
3. Если смена активна → **`ActiveShiftPanel`**:
   - сверху pill-style таб «Получить крой / Сканировать паспорт»
     (полностью переключает форму, фокус автоматически возвращается
     в input после каждого ответа сервера);
   - крупный input под QR (моноширинный, с дашед-рамкой);
   - primary-кнопка «Получить крой» / «Принять на операцию»;
   - результат — `.result-card` (`--issue` зелёная, `--scan` синяя)
     с номером паспорта, изделием, размером и количеством;
   - ошибки — `.error-box` с `requestId`;
   - внизу — небольшая danger-кнопка «Завершить смену».

### 4.3. `/passports/[id]`

Полностью пересобран в mobile card layout:

- **Hero-блок** (`.passport-hero`): QR слева, заголовок + статус +
  ключевые поля справа, primary-«Печать» и secondary-«К заказу».
- **Качество (ОТК)** — три цифры (Раскроено / Брак / Годных) в
  тонированных плашках, кнопка «Открыть в ОТК» (если статус
  IN_PROGRESS).
- **Упаковка** — короткий статус-параграф с ссылкой на коробку или
  на `/packing`.
- **Начисления** — три суммы и таблица (на мобильном горизонтально
  скроллится).
- **Размещение в ячейке** — `<PlaceForm>` в мобильном виде (два
  поля + крупная кнопка) для статуса `CREATED` без ячейки.

### 4.4. `/` (главная)

Для авторизованного пользователя — приветствие + плитка
`<MobileActionCard>` по разделам (Работа / ОТК / Упаковка /
Зарплата / Заказы; для менеджера — ещё Цех). Для гостя — короткий
CTA «Войти».

### 4.5. Supporting screens

`/qc`, `/packing`, `/orders`, `/earnings`, `/admin`, `/shopfloor` —
не переделывались по шаблонам, но получили новую палитру через
токены: чище таблицы, мягкие тени, новые радиусы и кнопки.

---

## 5. Адаптив

- `≤ 900 px` — верхняя навигация скрывается, включается
  `<MobileNav>`. Контент получает `padding-bottom`, чтобы не
  перекрываться нижней панелью.
- `≤ 640 px` — компактный хедер (роль скрыта, имя обрезано),
  `.action-grid` остаётся 2×N, формы становятся одноколоночными.
- `≥ 1500 px` — `/shopfloor` увеличивает шрифт цифр для
  ТВ/моноблока (без изменений со Шага 10).

---

## 6. Что осталось намеренно простым

- Никаких иконок-шрифтов и UI-библиотек — только Unicode-глифы
  (`✦`, `✓`, `▦`, `≡`, `⌂`, `₽`, `◫`). Этого достаточно для цеха
  и не тащит десятки килобайт.
- `<MobileNav>` не строится по ролям: 4 ключевых раздела и всё.
  Лишние пункты для конкретной роли просто не используются.
- Tabs «Получить крой / Сканировать» намеренно делают одно действие
  одной формой — без вкладок-сохраняемого-состояния, чтобы поток
  «бить QR подряд» не расходился с ожиданиями.

См. также `docs/screens.md` (карта экранов) и
`docs/pilot/operator-checklist.md` (чек-листы для ролей).
