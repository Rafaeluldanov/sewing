# ADR-0004: Упрощённая модель ячеек

- Статус: принято
- Дата: 2026-04-17

## Контекст

ТЗ §11 явно требует НЕ делать:
- статус «занято/свободно»;
- историю размещения.

Нужно только текущее содержимое: `ячейка → размер → количество`.

## Решение

- `Cell { id, code, qrCode, active }`.
- `CellContent { cellId, sizeId, quantity }` с уникальным `(cellId, sizeId)`.
- Изменения — через `POST /api/cells/place` и `POST /api/cells/remove`.
- Историю фиксирует только `PassportEvent(CELL_PLACED|CELL_REMOVED)` —
  этого достаточно для аудита.

`quantity` — целое, валидация: не может стать отрицательной (422).

## Последствия

+ Простая модель, быстрая реализация.
− Нет физической привязки «паспорт X лежит в ячейке Y». Для MVP это ОК:
  перемещения паспорта идут по операциям, а ячейка — промежуточное хранение.
