# ADR-0003: Event-sourcing lite для паспорта

- Статус: принято
- Дата: 2026-04-17

## Контекст

Нужна история всех действий с паспортом, плюс быстрый доступ к текущему
состоянию. Полноценный event sourcing дорог для MVP, но журнал событий
обязателен для учёта и будущих аналитик.

## Решение

**Гибрид:**

1. Текущее состояние — колонки на `Passport` (`currentOperationId`,
   `status`, `qtyCut`, `qtyDefect`, `qtyGood`).
2. История — `PassportEvent[]` (append-only).
3. Любое изменение состояния пишет событие **в той же транзакции**
   (`prisma.$transaction`).

Никаких асинхронных очередей на MVP. `@nestjs/event-emitter` — только
для «рыхлых» слушателей (инвалидация кеша), не для денег.

## Последствия

+ Детерминированность: текущее состояние и история всегда согласованы.
+ Простой read-path (без reducers).
+ Возможность future-proof: перейти к полноценному ES без слома схемы.
− Двойная запись (`Passport` + `PassportEvent`) — надо не забывать.
