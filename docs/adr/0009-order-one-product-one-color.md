# ADR-0009: Один заказ — одно изделие и один цвет

- Статус: принято
- Дата: 2026-04-17
- Контекст шага: Шаг 4 MVP (модуль заказов)

## Контекст

По ТЗ §14 заказ группирует позиции по размерам. На MVP бизнес-сценарий
начальника цеха — создать заказ на одно изделие в одном цвете с
разбивкой по размерам. Схема `OrderItem` уже содержит `productId`,
поэтому формально допустима любая комбинация «заказ × много продуктов».
Нужно было решить, хранить ли цвет на заказе или на продукте, и нужно ли
разрешать разные продукты в одном заказе.

## Решение

1. **Один заказ = один `productId` + один цвет + много размеров.**
   Валидируется в `OrdersService` (все строки получают один и тот же
   `productId` при создании; при PATCH допускается смена продукта целиком).
2. **Цвет хранится в `Order.color` (nullable).** По умолчанию
   подставляется из `Product.color` при создании; при необходимости может
   быть перезаписан вручную (например, партия нестандартного оттенка).
   Это избавляет от ситуации «продукт переименовали — цвет заказа поехал»
   и не требует развязывать Product на два поля (name, color).
3. **Ограничение «один размер на заказ»** защищается `@@unique(orderId,
   productId, sizeId)` в `OrderItem` — уникальность гарантируется БД.

Поля `orderDate` (обязательное) и `comment` (опциональное) добавлены на
`Order` в этом же шаге — см. `docs/erd.md §2.7`.

## Последствия

- Форма создания заказа в UI простая: один `select` изделия и сетка
  размеров. Нет сложной логики мульти-продукта.
- Если позже бизнесу понадобится «заказ на несколько изделий», придётся
  либо создавать несколько заказов, либо снять валидацию и развить UI —
  смена не ломает базу.
- Цвет можно задать вручную, но обычно он тот же, что у продукта.
- План заказа остаётся иммутабельным по ADR-0006 после перехода в
  `IN_PRODUCTION`.
