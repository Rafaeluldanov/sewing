# ADR-0002: Паспорт изделия — агрегат-корень

- Статус: принято
- Дата: 2026-04-17

## Контекст

Бизнес-требование: всё производство «вертится вокруг паспорта». Паспорт
определяет партию (размер+цвет+рулон), несёт план/факт, брак, участвует
в учёте зарплат, проходит все операции.

## Решение

`Passport` — агрегат-корень. Остальные сущности ссылаются на него:

- `PassportEvent` — журнал изменений состояния.
- `OperationEntry` — финансовая запись, всегда с `passportId`.
- `BoxItem` — вхождение паспорта в коробку.
- `Cell` напрямую не ссылается, но изменения ячейки фиксируются событием
  `CELL_PLACED/CELL_REMOVED` с `passportId`.

Все бизнес-операции, меняющие состояние паспорта, — **методы сервиса
PassportService** или смежных, работающие в транзакции с журналом
событий.

## Последствия

+ Прозрачная модель: всегда понятно, «что случилось с партией».
+ Возможность полного аудита (восстановление истории).
+ Упрощённый RBAC: действия привязаны к агрегату.
− Денормализация: `currentOperationId`, `qtyGood` хранятся на `Passport`
  и должны обновляться синхронно с событиями.
