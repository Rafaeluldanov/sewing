# Ассистент (ИИ) в админке

> Источник истины по фиче «окно диалога с ИИ». Если код расходится с этим
> документом — правим код. Дата: 13.08.2026. Этап 0 (только чтение).

---

## 1. Что это и зачем

Окно «Спросить» в правом нижнем углу админки. Сотрудник задаёт вопрос
своими словами — ассистент отвечает, вызывая read-only инструменты поверх
данных тенанта, и показывает ссылки-источники, по которым ответ можно
проверить глазами.

Два класса вопросов:

- **данные** — «сколько заказов в производстве», «где паспорт P-…»,
  «что тормозит цех», «какая потребность по заказу»;
- **устройство системы** — «что значит статус “Расчёт готов”», «как
  работает маршрут», «где смотреть деньги».

Чего ассистент НЕ делает на этапе 0: ничего не меняет, не считает деньги
сам, не строит сценарии «а что если», не обходит права.

---

## 2. Ключевое решение: границы в коде, а не в промпте

Промпт можно обойти уговорами. Поэтому все границы стоят до модели:

| Граница | Как обеспечена |
|---|---|
| Тенант | Инструменты ходят через `PrismaService` — Proxy по `TenantContext` (AsyncLocalStorage). Весь агентный цикл живёт внутри await-цепочки обработчика; обращение к БД вне контекста запроса падает громко. |
| Роли | Ручки под `@Roles('SHOP_MANAGER','ADMIN')`. Инструменты не расширяют права: они читают ту же БД тенанта, что и обычный запрос. |
| Группы данных | `PRODUCTION` / `SUPPLY` / `MONEY` / `PAYROLL`. Выключенная группа **не попадает в запрос к модели**: `toolsForScopes` фильтрует набор до обращения. Модель не может позвать то, чего ей не дали. |
| Мутации | Их нет физически. Ни одного `create`/`update`/`delete` в `assistant-tools.ts`. |
| Деньги | `order.estimate` отдаёт **уже посчитанную** смету. Самостоятельный пересчёт разошёлся бы со сметой, «Операциями», «Сводно» и плановой себестоимостью — это четыре согласованные поверхности (см. `docs/domain.md`). |

Деньги и зарплата выключены по умолчанию — включение это осознанное
решение владельца, а не побочный эффект обновления.

## 4. Инструменты

| Инструмент | Группа | Что отдаёт |
|---|---|---|
| `orders.search` | PRODUCTION | Заказы по статусу/клиенту/просрочке + счётчик |
| `order.get` | PRODUCTION | Один заказ: статус, расцветки, готовность |
| `passport.locate` | PRODUCTION | Где паспорт: в работе / последняя пройденная операция, держатель, ячейка |
| `production.queue` | PRODUCTION | Очередь по операциям — где узкое место |
| `workshop.needs` | SUPPLY | Потребность в материалах по заказу |
| `order.estimate` | MONEY | Готовая смета (не пересчёт) |
| `docs.lookup` | — | Справка об устройстве системы |

**Засада, на которую напоролись при разработке.** `Passport.currentOperationId`
значит РАЗНОЕ в зависимости от `currentEmployeeId`: пока паспорт у
исполнителя — это операция в работе, после сдачи туда пишется
ЗАВЕРШЁННАЯ операция, а исполнитель обнуляется (`passports.service.ts`,
`afterSnapshot`). Отдавать это модели под одним именем «текущая операция»
нельзя — она ответит «шьётся на распошивалке» про паспорт, который там
уже отработал. Инструмент отдаёт два разных поля:
`operationInProgress` и `lastCompletedOperation`.

**Справка едет в коде, а не читается с диска.** Каталог `docs` не
копируется в образ API (`apps/api/Dockerfile.prod`), поэтому инструмент,
читающий `docs/*.md`, на dev работал бы, а на проде молча ничего не
находил. Статьи лежат в `knowledge.ts`.

## 5. Поток ответа (SSE)

Агентный проход с инструментами живёт 5–30 секунд. Молчащее окно всё это
время читается как «сломалось», поэтому ответ идёт потоком:
`thread` → `tool` / `tool_done` → `text`… → `sources` → `done`.

Три вещи, без которых поток рвётся:

1. **`proxy_buffering off`** на `/api/` — уже стоит во всех конфигах
   nginx, ничего добавлять не пришлось.
2. **Heartbeat `: ping` раз в 15 с.** `proxy_read_timeout 120s` — это
   бюджет ТИШИНЫ между байтами, а не общего времени ответа. Модель может
   молча думать дольше двух минут до первого вызова инструмента.
3. **Ожидаемые отказы — событием `error`, не HTTP-кодом.** Заголовки уже
   ушли; `throw` после `flushHeaders` дал бы `ERR_HTTP_HEADERS_SENT`
   поверх открытого потока (`GlobalExceptionFilter` безусловно делает
   `res.status().json()`).

## 6. Деньги и лимиты

Стоимость считается в **микродолларах** ($0,03 = 30000): типовой вопрос
дешевле цента, в центах всё округлилось бы в ноль и месячный потолок
перестал бы работать.

- суточный лимит на сотрудника — по **московским суткам**;
- месячный потолок на компанию — в центах, сравнивается с суммой
  `AssistantMessage.costUsdMicros` с начала календарного месяца;
- оба проверяются ДО обращения к модели.

Экономия на кэше префикса: системный промпт и описания инструментов
стабильны байт-в-байт (никаких дат и имён внутри — всё переменное уезжает
в сообщение пользователя). Повторное чтение префикса стоит ~10% от
обычного, поэтому любая «мелочь» вроде даты в системном промпте
удорожает каждый вопрос примерно вдесятеро.

Модель по умолчанию `claude-opus-5`, переключатель на `claude-sonnet-5`
(втрое дешевле). Усилие — `medium`: на вопросах «сколько заказов» и «где
паспорт» более глубокое размышление не улучшает ответ.

## 7. Конфигурация

| Переменная | Где читается | Смысл |
|---|---|---|
| `ANTHROPIC_API_KEY` | api | Платформенный ключ. Пусто ⇒ ассистента нельзя включить с источником «платформенный». |
| `FEATURE_AI_ASSISTANT` | web (RSC) | Шторка и карточка настроек. **Серверный флаг, не `NEXT_PUBLIC_*`** — сознательно: на build-time переменных мы уже обжигались, когда они не доехали до прода. |
| `INTEGRATION_SECRET_KEY` | api | Уже существует. Тем же ключом шифруется свой ключ Anthropic (BYOK). |

Ключ компании (BYOK) хранится в `IntegrationSettings.assistantApiKeyEnc`
и наружу не отдаётся никогда — в DTO только `hasOwnAssistantKey`.

## 8. Что дальше (не сделано на этапе 0)

- **Действия с подтверждением** — модель предлагает, человек жмёт кнопку.
- **Универсальный `api.get`** поверх `docs/api.md` как каталога — покрытие
  всего API одним инструментом на длинный хвост вопросов. Деньги и
  зарплату через него пускать нельзя (см. §2).
- **Инструменты группы PAYROLL** — сейчас группа есть в настройках, но
  инструментов в ней нет: тумблер включается, а поведение не меняется.
- **История диалогов в UI** — треды пишутся в БД, но списка диалогов в
  шторке пока нет.
- **Tool search** — когда инструментов станет больше пары десятков, их
  описания перестанут помещаться в разумный промпт.
