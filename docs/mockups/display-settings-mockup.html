Цеховой монитор: выбор окон и подразделения

Сейчас /shopfloor/display показывает всё сразу и всем одинаково: 8 KPI-плиток, матрицу «цвет × размер» со всеми колонками операций пошива, ОТК, ВТО, упаковкой и готовым, панель оборудования и вызовы мастера. На ТВ у раскройщиков половина этого — шум, у швей — другая половина.

Предложение: набор видимых окон становится настройкой экрана, рядом с уже существующей настройкой подразделения. Ничего нового изобретать не нужно — подразделение экрана уже живёт в DisplayScreenConfig.companyDivisionId (админка «Display-экраны»), туда же ложится и список окон.

Два входа, один источник истиныПостоянная настройка — карточка экрана в админке (переживает перезагрузку ТВ и чистку кэша). Шестерёнка на самом дисплее — быстрый подбор «здесь и сейчас», результат можно одной кнопкой записать в карточку экрана.
Шестерёнку видит не каждыйТот же гейт, что и у drill-in: только ADMIN / SHOP_MANAGER. Под учёткой DISPLAY экран остаётся витриной без единой кнопки — в цехе крутить настройки некому.
Дефолт не меняетсяПустая настройка = «показывать всё», как сегодня. Существующие экраны и TV-закладки продолжают работать без миграции данных.
Подразделений можно выбрать несколькоОдно, два, все — набор галочек вместо выпадающего списка. Отдельно решается, складывать выбранные в один итог или показывать раздельными полосами: «ТВ на два потока» и «ТВ общей сводки» — это разные экраны, а не разные фичи.
Окна выключаются, раскладка сходитсяВыключили оборудование — матрица занимает всю ширину. Выключили KPI — таблица получает по вертикали ~15 % площади. Никаких дыр на месте скрытых блоков.

Второй режим — на будущее: витрина сама перелистывает включённые окна. В первой версии можно не делать.
Панель открыта поверх живого экрана. «Только сейчас» — настройка остаётся в URL и уходит при закрытии вкладки; «Сохранить в карточку экрана» — пишется в БД и подхватится этим ТВ после перезагрузки.
Панель оборудования подразделению не подчиняется. Так сделано сегодня и осознанно (shopfloor.service.ts): станок не принадлежит подразделению — между сменами на нём шьют разные заказы. Значит, при выборе «Пошив-1 + Пошив-2» матрица и KPI сузятся, а плитки станков останутся все. Если на ТВ нужны только «свои» машины — это отдельная задача про привязку оборудования к подразделению, и решать её надо в справочнике оборудования, а не настройкой экрана.
Почему счётчики внутри выключенного окна залочены: подпункты — это часть окна. Выключили «Оборудование» — его подпункты гаснут вместе с ним, но галочки не теряются: включили обратно — вернулась та же конфигурация.

2. Что видит цех после настройки

Тот же экран с настройками из панели выше: два подразделения раздельными полосами, 6 KPI вместо 8, без колонок ВТО, без панели оборудования. Матрица занимает всю ширину и становится читаемой с другого конца зала — это и есть смысл всей затеи. KPI-лента над матрицей всегда суммарная по выбранным подразделениям: восемь плиток × число подразделений — это опять та же массовка, от которой уходим.

4. Контракт и объём работ

Дельта поверх существующего кода — намеренно узкая.

МестоЧто меняется
prisma/schema.prisma → DisplayScreenConfig+ поле panels Json?. null = показывать всё (обратная совместимость, миграция без бэкфилла).
prisma/schema.prisma → DisplayScreenDivision (новая)Связка many-to-many «экран ↔ подразделение»: displayScreenConfigId, companyDivisionId, @@unique([displayScreenConfigId, companyDivisionId]), onDelete: Cascade с обеих сторон. Миграция переносит текущий одиночный companyDivisionId в строку связки; само поле оставляем нетронутым до полного переезда, читать перестаём сразу. Пустая связка = все подразделения — ровно тот же смысл, что null сегодня.
packages/shared/src/display-screens.ts+ DisplayPanelsSchema (zod) с дефолтами и + resolveDisplayPanels() — одна функция, которая из null | частичный JSON | query-строка собирает полный объект. Клиент дисплея и админка используют её же.
display-screens.service.ts+ PATCH /api/display-screens/:id (сейчас есть только list / create / archive). Правит name, список подразделений, panels, isActive. Несуществующая карточка подразделения в списке → тот же 400 COMPANY_DIVISION_NOT_FOUND, что и на create.
shopfloor.service.tsresolveDisplayDivisionCode → resolveDisplayDivisionCodes (возвращает массив), фильтр заказов companyDivision.code → { in: [...] }. Панели отдаются в GET /api/shopfloor/display тем же ответом, что и данные. Данные не режем на backend'е: агрегаты дешёвые, а резать на клиенте — значит мгновенно переключать окна без ожидания запроса.
shopfloor-projection.ts ← основной объёмРаздельный режим добавляет матрице третье измерение: сегодня проекция группирует цвет × размер, нужно подразделение → цвет × размер плюс итог по подразделению. Значит, в выборку паспортов едет order.companyDivision {code, name}, а ShopfloorDisplayDto получает уровень блоков подразделения. Суммарный режим (галочка снята) — это ровно сегодняшняя проекция с фильтром in, ноль изменений; если хочется сделать фичу в два захода, раздельный режим отделяется вторым шагом.
apps/web/app/shopfloor/display/display-board.tsxУсловный рендер 4 блоков + подпунктов, панель-drawer (только при drillIn), запись «только сейчас» в URL.
apps/web/app/admin/display-screens/[id]/Новая страница-карточка (сейчас её нет вовсе) + server action на PATCH.
docs/display-board.md, docs/screens.md §10e, docs/api.md §33Описание поля panels, нового PATCH и приоритета источников.

Приоритет источников (сверху вниз)

ИсточникКогда
?panels=… / ?divisionCode=01,02 в URLОтладка, «только сейчас» из панели, старые TV-закладки. Перебивает всё. Формат прежний, просто через запятую — одиночный ?divisionCode=01 продолжает работать без изменений.
DisplayScreenConfig учётки DISPLAYОбычный режим ТВ в цехе. Ровно то, что настроили в админке: связка подразделений + panels.
Дефолт «показывать всё»Экран без карточки (админ открыл дисплей со своего ноутбука), пустая связка подразделений и все существующие экраны до первой настройки.

Формат panels

// DisplayScreenConfig.panels — все ключи опциональны,
// отсутствие ключа = значение по умолчанию (true)
{
  "kpi": { "on": true,
           "cards": ["producedToday","inWork","waiting","qc","finished","defect"] },
  "matrix": { "on": true, "sewing": true, "qc": true, "wto": false,
              "post": true, "colorTotals": true,
              // раздельные полосы по подразделениям; false = один общий итог
              "byDivision": true },
  "equipment": { "on": false, "totals": true, "sizes": true },
  "calls": { "on": true }
}

// сами подразделения — НЕ здесь, а строками DisplayScreenDivision:
// это FK на справочник, а не настройка вида. Пустая связка = все.

// та же настройка короткой строкой в URL (для закладки/отладки):
// ?divisionCode=01,02&panels=kpi:producedToday+inWork+waiting+qc+finished+defect,matrix:-wto+byDivision,calls
Что сознательно НЕ входит в первую версию: перелистывание окон по таймеру (селект в панели показан как задел), фильтр по конкретным заказам или цветам, и разные наборы окон по расписанию (день/ночь). Всё это — надстройки над тем же полем panels, если понадобится.
